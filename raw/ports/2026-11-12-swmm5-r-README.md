# swmm5-r

EPA SWMM 5.2.4 in R, written by a translator that reads EPA's C, and judged against EPA itself: the binary `.out`
file byte for byte, and the `.rpt` report line for line except the three lines that print the wall clock.

**Result: 465 of the 480 gate models identical to EPA 5.2.4; the other 15 not run (timed out after 1800 s), each
identical to EPA's output as far as it had got; none differs.** An independent rerun of a sample from a clean
checkout: 102 of 103 identical, 1 not run (timed out after 1800 s). R runs SWMM about 400 times slower than EPA's C.

It is not a new engine and not a wrapper: there is no C in it (no `.C`, `.Call` or `dyn.load`), it calls no other
port, and it uses base R only. Every number it writes is EPA 5.2.4's, including the results of EPA's own defects
wherever EPA's behaviour is defined (`lessons/02-epa-defects-found.md`). R is one of the languages of Bob
Dickinson's Code Rosetta Stone app.

## The parity contract

The same as the earlier ports' (see `go/` or the swmm5-go repository): EPA SWMM 5.2.4 built from the USEPA v5.2.4
tag with gcc 13.3 `-O2` on x86-64 Linux with glibc 2.39 (`ref/Makefile`), on a processor with FMA and AVX2; each
model run in its own folder; pass = `.out` byte-identical (when EPA writes one) and `.rpt` identical after removing
`Analysis begun on`, `Analysis ended on` and `Total elapsed time`, the exit code the same (EPA's command line always
exits 0). When an input error stops EPA before it writes results, the engine must not write a results file either.
Corpus: the 480 gate models of `gate/models_all.tsv` from SWMMBobSWMM6/1729-SWMM5-Models-2030.

## Run

Requires **R 4.3.3** (Ubuntu's `r-base-core`, `Rscript`), base R only: the engine uses the `base`, `compiler` and
`stats` packages that come with R. gcc is used only by the runtime checks, to write glibc's reference values.

```sh
r/build.sh                                        # once: byte-compiles the two engines (about 40 s)
r/runswmm model.inp model.rpt model.out           # = Rscript --vanilla r/runswmm.R ...
```

To regenerate the engines: `python3 tools/c2x/emit_r.py r/swmm5` from the repository root (needs
`pip install libclang==18.1.1`, the clang 18 headers at `/usr/lib/llvm-18/lib/clang/18/include`, and `Rscript`,
which the translator asks once whether R reads each decimal literal exactly; about 1 minute). It writes
`r/swmm5/engine.R` and `r/swmm5/engine_fast.R`.

## How it was made

`tools/c2x/front.py` parses EPA's C with libclang; `tools/c2x/emit_r.py` subclasses the Python back end
(`emit_py.py`) for its analysis (the front end's pointer modes, names made unique per function, string literals) and
writes all of its R itself. When the port disagreed with EPA, the fix went into the translator or the runtime, never
into the generated files. The mapping, in full in the emitter's header:

- **Numbers.** Every C integer and floating type is an R double. R's own integers are 32-bit, turn an overflow into
  NA, and its `%/%` and `%%` floor where C truncates; doubles hold every integer EPA computes exactly. C's integer `/`
  is `trunc(a / b)` (exact for 32-bit operands), `%` is `a - trunc(a / b) * b`, an `unsigned` result is reduced with
  `%% 4294967296`, `<<` and `>>` are a multiplication and a floor division by a power of two, and `&`, `|`, `^` go
  through the runtime on 16-bit halves (R's `bitwAnd` takes 32-bit integers and cannot hold 0x80000000, which is NA).
  `(int)x` and `(long)x` of a double are written inline as x86-64 does them: truncation, and the "integer
  indefinite" value INT_MIN or LONG_MIN for NaN and out-of-range values (EPA relies on it: lessons/02, defect 2).
  `(float)x` is `rt_f32`, a 4-byte `writeBin`, which is C's cast (cvtsd2ss).
- **Values and references.** R vectors and lists are values: assigning or passing one and then changing it changes
  a copy. Environments are references. So a C struct is an environment (constructor `T_<struct>`, clone
  `K_<struct>`, copy-into `C_<struct>`); a struct assignment copies into the existing environment, so an array of
  structs, a plain R list of environments, never changes after it is made. An array of numbers or pointers is a
  reference array: an environment whose field `v` holds the vector (`rt_ra`), so a function that fills an array it
  was given fills the caller's. `char*` is a CPtr, `list(buffer, offset)`, the buffer a reference array of byte
  values. A pointer to a number is a box (an environment with field `v`). A C local whose address is passed to a
  function stays a plain R local and goes through a box for the call, copied in before and out after (no EPA
  function keeps such a pointer); `&s.f` and `&a[i]` go through a temporary box the same way.
- **Lists and NULL.** `x[[i]] <- NULL` deletes an element of an R list; a store of a pointer into a list is written
  `x[i] <- list(value)`.
- **Laziness.** R evaluates a function's arguments when the function first uses them; C evaluates them before the
  call. Every generated function starts by evaluating its parameters in order (`a; b; c`), which forces them at once.
- **Assignment.** A path rooted at a local is assigned with `<-`, at a global with `<<-` (assigning `<-` to a global
  would make a local copy); a field of a struct reached through an expression is assigned through a temporary
  (`{.e <- Node[[j + 1]]; .e$newDepth <- v}`), so only the environment's own binding is touched. Assignments are
  expressions in R, so C's `if ((f = fopen(...)) == NULL)` keeps its shape.
- **Statements.** if / else if / else, while, repeat; do-while is `repeat { ...; if (!(c)) break }`; `for` is a while
  loop with the increment repeated before every `next`; `switch` is an if / else if chain, or a one-pass `repeat`
  loop with a fall-through flag when a case falls through; `return(x)`.
- **Names.** R's reserved words and names that would hide a base function the engine calls get a trailing `_`
  (`length_`, `q_`, `next_`); the translator's own names begin with a dot (`.e1`, `.c`), which C names cannot.
- **Constants.** Enum constants and numeric macros are written as their values. R's parser does not always round a
  decimal literal correctly (`as.numeric` differs from glibc's strtod on 30 of the 199,988 plain decimals of the
  runtime check), so the translator asks R once how it reads every non-integer literal it writes and would write
  any that R reads inexactly in hexadecimal; for EPA's literals the answer was none.
- **Speed without changing what is computed.** A global that a function reads twice or in a loop, and that neither it
  nor anything it can call assigns as a whole (call graph, a call through a function pointer counting as a call to
  every function whose address is taken), is read once into a local at entry; a local is not zero-initialised when
  the first statement that mentions it assigns it; the engine is byte-compiled once (`build.sh`) and loaded compiled.

### NaN, and why there are two engines

A comparison with NaN is false in C (true for `!=`); in R it is NA, and `if (NA)` is an error. Several gate models
compute NaN (two print `-nan` in EPA's own report), so every comparison of floating values must give C's answer.
Written out, `if (a < b)` becomes `if (!is.na(.c <- (a < b)) && .c)`, and `is.na` is a call to a builtin: about 0.15
microseconds each, on every comparison of doubles in the engine.

The translator therefore writes two engines from the same C. The **safe engine** (`engine.R`) writes every
comparison of floating values, every double used as a condition and every `(int)` cast in that NaN-proof form. The
**fast engine** (`engine_fast.R`) writes them as R's plain comparisons, so a NaN that reaches one is an NA, and R stops
with an error ("missing value where TRUE/FALSE needed"). `runswmm.R` runs the model on the fast engine; if it stops
with an error, it closes the files the engine opened, removes its temporary files and runs the model again from the
start on the safe engine, whose outputs replace the first run's (EPA opens the report, results and SAVE files for
writing, which truncates them). The fast engine never gives a different answer silently: a NaN in an `if`, `while`,
`?:` or a comparison used as a number is an error, and `NA && FALSE` (FALSE) and `NA || TRUE` (TRUE) are what C
gives whatever truth value the NaN had. What R does differently is evaluation order: it evaluates `x` in both
`NA && x` and `NA || x`, where C evaluates it only after a true left operand of `&&` or a false one of `||`. A plain
comparison with NaN is false in C, so the left operand of an `&&` whose right operand has side effects is written
NaN-proof in the fast engine too, and so is the left operand of such an `||` when it holds a `!=`, a `!` or a double
tested as a condition (NaN is true there; EPA's code has none, lessons/45). The gate's two NaN models
(Hydraulics/Allow_Ponding_Low_CE.inp and Hydraulics/swmm5_shapes.inp) run this way.

### Memory: what C allocates but never touches

R zero-fills a vector when it makes it; C's calloc only reserves address space, and nothing is resident until it is
written. rdii.c keeps, for every unit hydrograph, a circular array of past rainfall as long as the hydrograph's time
base over the rain interval; Hydrology/sewer_rdii_problem.inp has 613 hydrographs with a 9,900-hour base and a
60-second interval, 375 million values that EPA almost never touches, and the first R run was killed by the
out-of-memory killer at 6 GB (lessons/46). `overrides.R` has hand ports of `allocRdiiMemory`, `updateDryPeriod` and
`getUnitHydConvol` in which an empty array stands for an array of zeros: the arrays grow as EPA writes them (always
at the next index), the start of an RDII event empties the past rainfall instead of storing 0.0 in every entry, and
the convolution takes an entry past the end as 0 and adds the same terms in the same order, skipping those that add
nothing. These three functions run only when a node has RDII inflow.

## The runtime and the math library

- **printf, strtod, sscanf** (`rt.R`). R's `sprintf` hands a floating conversion to the C library's `snprintf`, so
  `rt_format` parses each C format and passes every finite `%f`, `%e` or `%g` to it one conversion at a time; R
  prints NaN and infinities its own way (`NaN`, `Inf`), so those, signs and padding included, are written by the
  runtime as glibc writes them (`-nan`, `inf`); `%s` and `%c` are padded on the bytes; integers go to `sprintf` as R
  integers, and values beyond 32 bits are formatted from 16-bit limbs (`%lu` of a negative long is its two's
  complement). A parsed format is cached only for a string literal (lessons/39). `as.numeric` is R's own
  `R_strtod`, not glibc's strtod, and is not always correctly rounded, so `rt_scan_double` finds the extent of a
  number by glibc's rules (hexadecimal floats, `inf`, `infinity`, `nan(n-char-sequence)` with its payload) and
  converts it exactly: one correctly rounded multiplication or division of exact doubles when the number has at most
  15 significant digits and a small exponent; otherwise an estimate from `as.numeric`, corrected by comparing the
  exact decimal with the midpoints between neighbouring doubles in big-integer arithmetic (base-2^24 limbs; a
  midpoint is built from its integer parts, since a double cannot hold it). sscanf's `%f` into a C `float` rounds
  once, as glibc's strtof does.
- Checked against glibc 2.39 by `r/test/run_crtcheck.sh` (the 1,394,252 cases from `tools/crt/test/mkfmt.c` that the
  other runtimes replay): **0 of 1,389,850 differ** (`r/results/crtcheck_result.txt`), `%#g` included. The 4,402
  `%ld` cases whose value is 2^53 or more in magnitude were not run: an R double cannot hold such a long, and the
  engine never computes one.
- **Math.** `libR.so` imports exactly the libm symbols EPA imports, at the same versions (`exp@GLIBC_2.29`,
  `log@GLIBC_2.29`, `pow@GLIBC_2.29`, `sin@GLIBC_2.2.5`, ...; `nm -D`), but R does not always call them as C does:
  `log(x)` returns R's own NaN (sign bit clear) for x < 0 and for a NaN, where glibc's has the sign bit set or keeps
  the argument's; `log10` of a NaN is R's NaN, not the argument; and `x ^ y` is `R_pow`, which squares (`x * x`) when
  y is 2, where glibc's `pow(x, 2)` differs from `x * x` in the last bit now and then (12,953 of 20,000,000 arguments,
  lessons/40), and
  which decides zero, infinite and NaN arguments by rules of its own (`(-Inf) ^ 1.5` is NaN in R, +Inf in C). So the
  engine calls R's `exp`, `sin`, `cos`, `tan`, `asin`, `acos`, `atan`, `sqrt`, `floor`, `ceiling` and `abs`
  directly, `rt_log` and `rt_log10` for log and log10, and for pow: `x ^ y` where it is glibc's (finite nonzero x,
  finite y other than 2; for a constant exponent that is not an integer the translator writes it inline, guarded
  only against -Inf), the special cases of glibc's `e_pow.c` written out for zero, infinite and NaN arguments, and,
  for `pow(x, 2)`, R's `qweibull(-|x|, 0.5, 1, FALSE, TRUE)`, which is `1 * pow(-p, 1 / 0.5)` computed by glibc's
  pow inside R's math library: glibc's own `pow(|x|, 2)`, which is `pow(x, 2)`. No glibc code was translated for
  this port.
- Checked bit for bit, NaN signs and payloads included, by `r/test/run_libm_tests.sh` (`test/libmcheck.R`), each
  function as the engine calls it: 11,000,672 random arguments over SWMM's ranges plus special values
  (`tools/libm/test/mkvectors.c`), 3,300,000 edge cases (`mkedge.c`), and 8,000,360 cases (`test/mkexact.c`, from
  the Hy port's) for sqrt, floor, ceil, fabs, negation, `(float)`, and the safe and fast forms of `(int)` and
  `(long)` (the fast forms must stop on NaN, and did): **0 differ** (`r/results/libm_tests.txt`), except where the
  argument is a signaling NaN (exp, sin, cos, tan, asin, acos, atan, sqrt, floor, ceil: 663 cases in all), which R
  hands back unchanged without calling the C library and glibc returns quieted. No SWMM value can be a signaling
  NaN: arithmetic produces quiet NaNs and the runtime's strtod builds quiet ones.

## Speed

On the 465 models that passed, the R port took 37,055 s in all (the gate's per-model times, which include starting R
and loading the compiled engine, about 0.6 s), EPA's C 91.4 s and the Hy port 4,402 s: about 400 times EPA's time
and 8.4 times Hy's; the median model took 6.2 s. Measured on the shared 2-core machine under `nice -n 10`, one model
at a time, with another agent's gate runs waiting for the same lock, so these are rough. The 480 took 64,056 s of
model time and 19.4 hours from the start to the end of the gate runs (69,760 s, queueing excluded), from 10 November
20:23 to 12 November 02:02 with the waits for the lock.

Where the time goes: every C operation is an interpreted R operation on a boxed double, every struct field is an
environment lookup, and every array element access goes through an environment's `v`. What was tried and kept is
listed under "Speed without changing what is computed" above; jump tables for `switch`, removing the argument
forcing and the compiler's optimisation level 3 made no measurable difference and were left out.

## What this does not show

- That SWMM is right: identical to EPA means EPA's answers, good or bad.
- The 15 models that need more than 1800 s in R: they were stopped, and only what they had written by then was
  compared with EPA's output.
- Other platforms: R calls the system libm, so on another machine the port should follow EPA built there; only
  x86-64 Linux with glibc 2.39 and R 4.3.3 was run. Another R build could route a math function differently (the
  checks above would show it).
- `long` values of 2^53 or more: they are R doubles here, exact only up to 2^53. EPA computes none.
- Paths no gate model exercises: streets and inlets (one deck, which stops on input errors), climate files,
  USE HOTSTART, USE INFLOWS, USE RUNOFF; the stepping API is translated but only the command line was gated.
- A checked run in C's sense: R checks its list and vector bounds on reads, but a C overrun that stays inside an R
  vector would not show, and a write past the end of an R vector extends it silently.
- No person has reviewed the generated code line by line; the evidence is the gate and the runtime checks.
