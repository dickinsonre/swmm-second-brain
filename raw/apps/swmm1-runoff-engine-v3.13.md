# SWMM 1 Engine: the 1971 Storm Water Management Model, all five blocks, in the browser

**In one sentence.** This page runs the first Storm Water Management Model as it was printed in October 1971, all five blocks and 12,200 cards, and it reproduces a 1971 tide table to 0.0041 foot at worst and the 1971 flows of a San Francisco storm to the printed digit.

**In one paragraph.** SWMM Version 1 was a relay of five Fortran programs: an Executive Block that reads block names from cards, and Runoff, Transport, Storage and Receiving Water Blocks that pass hydrographs to each other on tape. All 235 listing pages of its 248-page Volume IV were typed back into Fortran and compiled to WebAssembly, so this page reads 1971 card decks and prints the 1971 report. Six runs printed in 1971 check the work: the two examples in the User's Manual and the four cities of Volume II. The estuary example matches 52 printed stage values to 0.0041 foot at worst. The sewer example matches except where one card changed between May 1970 and October 1971. A real storm on Baker Street, San Francisco, matches 88 of 95 printed flow and cost numbers to the digit, and points to one card, a conversion from minutes to seconds, as the likely reason the pollutant loads printed for it in August 1971 run far above this listing's: about sixty times at the storm's height, 33 times in total for BOD and 59 for suspended solids, with the edges of the storm not explained. A second real deck, for Philadelphia, reproduces the dry-weather flows printed for all 51 of its tracts. The last two, for Cincinnati and Washington, run as printed; the Washington deck reproduces 53 of the 55 design numbers printed for its storage basin and treatment plant.

## What it does
Runs the original SWMM Version 1 from its own Fortran, rebuilt from the scanned program listing. It reads 80-column card decks and writes the 1971 line-printer report and interface tapes. All five blocks run: Executive, Runoff, Transport, Storage, Receiving Water. It is for people who want to see what the first SWMM computed, and for anyone tracing a SWMM 4 or SWMM 5 method back to its first form.

## How it computes
- Source: every card of Volume IV, typed back into fixed-form Fortran with the identification field in columns 73-80.

| Block | Program units | Cards |
|---|---|---|
| Executive (MAIN, GRAPH, CURVE, PINE, PPLOT) | 5 | 389 |
| Runoff | 7 | 1,311 |
| Transport | 25 | 4,114 |
| Storage | 17 | 3,918 |
| Receiving Water | 11 | 2,468 |
| Total | 65 | 12,200 |

- Full-program engine: the listing, translated by f2c to C, compiled by Emscripten to WebAssembly (328 KB). A new module instance per run. Unit 5 is the deck, unit 6 the printout, other units are files `fort.N` in an in-memory file system.
- Build-time edits (temporary copy only, no arithmetic changed): `KILL` renamed `SKILL` (name clash); the two unnamed `BLOCK DATA` units named `TRBLK` and `STBLK`; in `INDATA`, `INQUAL`, `SWFLOW` one `DATA` card moved below the type cards (f2c statement order); `ARSIN(X) = ASIN(X)` supplied; COMMON blocks defined once at their largest declared size.
- Repaired engine (used only when "run with the 2026 repaired cards" is ticked): the same build after `tools/repair.py` changes five cards. `SROU 17` and `PLUG 21` (`DT=DT*60.0`) are removed and `SROU 74` and `PLUG192` (`9999 DT=DT/60.0`) become `9999 CONTINUE`, because STRAGE has already converted DT at `STRA 16`; `COMMON /TBLK/DT,NDT,KDT` is added to TRCHEK. The Run tab's first tile names the engine that made each run.
- Printer plots: the Plots tab finds every plot page in the printout (pages drawn by CURVE, PINE and PPLOT, 101 by 51 print positions) and draws each one as printed. A `GRAPH` block card plots any interface tape: cards `NTAPE,NPCV,NQP,NPLOT` (16I5), optional element list, title, horizontal label, `NQP+1` vertical labels (20A4).
- Runoff workbench engine: statement-for-statement C translation of the seven Runoff routines (version 1 of the app), used for Runoff-only decks and for the SWMM 5 `.inp` and SWMM 4 `.DAT` importers.
- Deck routing: a deck containing a block card (`WATERSHED`, `TRANSPORT`, `STORAGE`, `RECEIVING`, `ENDPROGRAM`) goes to the full program; any other deck goes to the workbench.
- Methods, as coded in 1971: Runoff, nonlinear reservoir on three planes per subarea with Horton infiltration (WSHED), gutter and pipe routing (GUTTER), surface quality (SFQUAL). Transport, elements sequenced upstream to downstream, kinematic wave by Newton iteration on normalized flow-area tables for 12 conduit shapes (ROUTE, NEWTON), dry-weather flow (FILTH), infiltration (INFIL), quality routing (QUAL). Storage, basin routing (STRAGE, SROUTE, PLUGS), a string of treatment units (TREAT), cost (TRCOST). Receiving Water, link-node explicit hydrodynamics (SWFLOW) and quality (SWQUAL, LOOPQL).

## Inputs and outputs
- Companion files: `pdf/SWMM1_Volume_I_Final_Report.pdf` (338 PDF pages), `pdf/SWMM1_Volume_II_Verification_and_Testing.pdf` (173 PDF pages), `pdf/SWMM1_Volume_III_Users_Manual.pdf` (359 PDF pages), read by the PDF tab; Volume IV (248 pages) is embedded in the HTML.
- Input: card decks (text, 80 columns). Executive header: title (10A4); `NSERYS,ACRES,ADDWF,NDESYR,DESFLO,NSTRMS,QTRUNK` (I5,F10.1,F10.2,I5,F10.1,I5,F10.1); `NSTRMS` storm cards (4A4,4A4); tape pairs `JIN,JOUT` (20I4); `NSCRAT(5)` (20I4); then block name cards, each followed by that block's cards; `ENDPROGRAM`.
- Interface tape (unformatted, 4-byte record markers): title (40 words); `NSTEP,NPOINTS,NQUAL,DT,TZERO,TAREA`; element numbers; then per step time, flow per point, `NQUAL` loads per point. Storage always reads unit 10 and writes unit 11.
- C source: Fortran tab, "Download the C (.zip)" gives `swmm1-c-source.zip`: `c/` (65 program units translated by `f2c -w -E -Nn802 -Nx400`, plus `commons.c` and `arsin.c`), `fortran/` (the listing with the build-time edits), `wmain.c`, build scripts. Native compile: `gcc -O0 -w c/*.c -lf2c -lm`. Machine-translated; as-printed cards only.
- Output: the printout (carriage control in column 1), every tape left on disk (charted and downloadable as CSV), and for Receiving Water the stage table parsed from the printout.
- Make a GIF (header button): records a 15-frame, 960 by 600 walkthrough inside the page and saves `swmm1_engine_walkthrough.gif` (about 675 KB, 40 s). It runs Runoff sample 1, then the Baker Street and Kingman Lake decks, draws each frame from the live page, and puts the user's deck back. html2canvas and gif.js are embedded, so it works offline and inside a claude.ai artifact.
- Importers (workbench only): SWMM 5 `.inp` and SWMM 4 `$RUNOFF` decks are converted to SWMM 1 Runoff cards. For a `.inp` the page shows a conversion inventory (every non-empty section marked Preserved, Converted, Approximated, Omitted or Unavailable; the label "Simplified SWMM 1 reconstruction" when a section that changes results has no translation) and a rainfall and time check. Rainfall rule since 3.6: a record keeps its calendar date, lasts one gage interval or until the next record, and is spread over the SWMM 1 blocks by overlap. Since 3.7: `CUMULATIVE` readings follow EPA SWMM 5 (`gage.c`, `convertRainfall`: a reading below the last one is a reset and counts in full); each gage's last record lasts that gage's own interval; the time step and the rain interval are chosen once, as they will be punched (`v37Timing`), and every card carries the same text with its decimal point written in (card 3 `F5.1`, card 4 `F5.0`, SFQUAL card Q1 `F5.0`; `NTSTEP = NSTEP`); the rain interval is a whole number of steps, because WSHED reads the rain histogram once, at the middle of each step (`WSHE 24`), and a step shorter than the request is chosen when needed (40 s against 5-minute rain becomes 37.5 s). The check reads the punched deck back with the 1971 FORMATs, steps through it as `WSHE 24` does, and compares each gage's depth with the file worked out from the records alone; each loss is named where it happens (spreading onto blocks, five-column fields, one reading per step), and rain outside the run is reported as outside the run. The snow catch factor is not applied. Green-Ampt: minimum rate = conductivity (second parameter), maximum rate = 3 times conductivity, a rule of thumb. Since 3.8: the runoff step is WET_STEP (hh:mm:ss, or decimal hours as EPA's `datetime_strToTime` reads a bare number), and 5 min when WET_STEP is absent (EPA `setDefaults`, `WetStep = 300`); ROUTING_STEP (a bare number is seconds) is reported and not used, because SWMM 1 Runoff routes its gutters and pipes at its one step; `LINK_OFFSETS ELEVATION` reads conduit end offsets as elevations (`*` = the node invert); rain records are clipped to the run before they are spread onto blocks, and a block cut by the end of the run carries its rain over the part inside the run; every physical field (subarea width, area, percent impervious, slope, roughness, storage, Horton rates and decay; gutter and pipe dimensions, length, slope, roughness; SFQUAL area and curb length) is punched with its decimal point and as many digits as its columns hold, with a leading blank only when no digit is lost. A geometry reader written apart from the converter (`v38Geometry`) reads the .inp's subcatchments and conduits with its own units and LINK_OFFSETS handling, reads the cards back with RHYD FORMATs 1060 and 1115, and compares 11 fields per subcatchment and 4 to 7 per conduit at 1 %. The converted deck is then also run on the full-program engine: an Executive header (title; `NSERYS,ACRES,ADDWF,NDESYR,DESFLO,NSTRMS,QTRUNK`; one storm card; `JIN,JOUT = 0,8`; `NSCRAT = 11..15`), `WATERSHED`, the cards with a GRAPH card `    0` in front of SFQUAL's first card, `ENDPROGRAM`. SWMM 4 imports get none of the read-back checks. Since 3.9: the infiltration method of each [INFILTRATION] line is its last token when that names a method, as EPA's `infil_readParams` reads it (`i = findmatch(tok[ntoks-1], InfilModelWords)`), so a subcatchment may differ from OPTIONS; the Green-Ampt stand-in is exactly maximum = 3 × conductivity and minimum = conductivity (the 0.5 in/hr floor is gone); an ELEVATION end below its node invert is raised to the invert, as EPA's `link_getOffsetHeight` does (warning WARN03 named in the caveats when it is more than 0.001 ft below); a 0 in a field RHYDRO defaults (RHYD 25: PCTZER 0 becomes 25; RHYD 75-82: slope 0.03, n 0.013 and 0.25, depression storage 0.062 and 0.184 in, Horton 3.0 and 0.52 in/hr, decay 0.00115) is punched as `.001` (`.00000001` for the decay constant) unless "SWMM 1 defaults for zeros" is ticked, which converts again with 0 punched.
- Run status (since 3.6, rebuilt in 3.7): separate rows after every run. Execution (ENDPROGRAM reached, or an expected historical stop: only for the three listed samples, unedited, on the cards as printed, with the 1971 message in the printout); Numerical validity (count of NaN and Inf values in the printout); Conservation (Runoff's printed continuity error, with the HYDR137 caution); Time axis (Runoff decks: the interface tape spans what card 3 asks for); Rainfall carried (imported `.inp`: the rain Runoff printed against the rain in the file, within 1 % or 1 cu ft, as Runoff prints whole cubic feet; since 3.12 it also fails when a subcatchment names a gage the .inp does not define); Routing carried (since 3.12, imported `.inp`: each subcatchment's card against its outlet, read again from the .inp, node first and then subcatchment as SWMM 5 reads it); Inputs carried (since 3.12, imported `.inp`: every input that changes runoff or flow and does not reach the cards: the Horton infiltration cap when it binds in this run, subarea routing, infiltration methods carried as stand-ins, LID, groundwater, snowmelt, dry-weather and external inflows, RDII, storage, flow regulators, controls, evaporation; CHECK when one changes this run's flows, APPROX when only carried approximately); Reference agreement. Each comparison is stored as data (kind, check, 1971 value, this run, tolerance, outcome) and shown as its own row. Four kinds are kept apart: printed 1971 result, printed measurement, figure read by eye, this app's earlier result. Only printed 1971 results count toward the Reference agreement row. Added in 3.8: Time axis compares three run lengths, the .inp's, card 3's and the tape's (the cards must be within half a step of the .inp); Geometry carried (imported `.inp`); Output tapes (each interface tape: records declared in its header against records present, and NaN or Inf values; a partial tape is also labelled on its chart and in the CSV with a `#` line); Second engine (imported `.inp`: tapes compared record by record, flows and loads within 0.1 % of each series' peak, printed rain, infiltration and inlet flow within 1 cu ft or 0.1 %). Added in 3.9: Effective parameters (imported `.inp`: each subarea field, card 3's PCTZER and each channel depth, .inp against the card run through RHYDRO's rules, RHYD 25, 75-82 and 167, and that value checked against the program's own printed subarea table, FORMAT 1070, and PCTZER line, FORMAT 1043, to half the last printed digit; since 3.13 each value has one of five outcomes, preserved (within 1 % or the last printed digit), approximated (a zero SWMM 1 cannot take, replaced by the smallest value its field holds, `.0001` or `.000000001`; a value the field width cannot hold within 1 %; a stand-in), historical default applied (a card value that makes SWMM 1 use its own default: asked for with "SWMM 1 defaults for zeros", or a fault), mismatch, or not checked against a printed table; approximations are graded for the run at hand: a slope is always material (EPA `subcatch_validate` leaves alpha at 0 for a zero slope), Manning's n always close (`findSubareaRunoff` routes nothing for a zero n), storage against the rain the subcatchment gets in the run and infiltration rates against that rain over the run's length (under 1 % negligible, under 10 % close, else material); the row is OK only when every value is preserved, APPROX when anything was substituted, CHECK on a mismatch or a default not asked for; stand-ins with no .inp counterpart, such as Green-Ampt, are listed and not counted). Second engine now runs after every workbench run whose deck has surface-quality cards (its position is found by walking the cards: rain, subareas to N = 0, gutters to N = 0, NSAVE list, NPRNT list), and it passes only if both tapes pass their own audits and their headers (NSTEP, NPT, NQUAL, DT, TZERO, TAREA), point numbers, record widths (1 + NPT × (1 + NQUAL)) and record times match before the 0.1 % numerical test.
- Run record (since 3.6, frozen since 3.7): made once when the run finishes; a repaint, a theme change or a tab change shows it and never rebuilds it. "Run record (.json)" saves the exact deck, the input tapes (base64), the inputs fingerprint (deck, engine, mounted sample tapes, keep-tapes switch), the finish time, app version, statuses, comparisons, time-axis and rainfall checks, conversion report, printout, and SHA-256 hashes. "Inputs changed since this run" appears on the Run, Printout and Plots tabs when the deck, the engine (repair switch), the mounted sample tapes or the keep-tapes switch differ from the run's, and says which. "Download current deck" saves the editor; "Deck that was run" saves the run's deck. Since 3.8 the inputs fingerprint covers the bytes of every tape mounted, kept tapes included; "put back the inputs of the run shown" mounts those recorded bytes and turns "keep tapes" off; when "keep tapes" is on and the kept tapes are this run's own outputs, the engine line says the next run continues the chain instead of marking the results stale. Each output tape in the record carries `records_declared`, `records_present` and `nonfinite_values`; the record also holds `geometry` and `second_engine`. Since 3.9 a workbench run takes its deck before its first `await` and keeps it, and a run number lets a newer run win over an older one still finishing; the record holds `effective_parameters`. Make a GIF restores the run object that was on screen, its frozen record included, instead of running the deck again.

## Bugs and quirks found in the October 1971 listing

Behavior of the cards as printed, found by running them. The as-printed engine keeps all of it; the optional repaired engine changes five cards (see the engines above).

- Storage with an orifice or weir outlet converts DT from minutes to seconds twice (`STRA 16`, then `SROU 17` and `PLUG 21`) and stops in `INTERP`; pumped outlets (`ISTOUT = 6`) work.
- TRCHEK tests DT with no COMMON card for it (`TRCH104`, `TRCH106`), so every deck with high-rate filters (`ITREAT(4) = 43`) is refused with "DT = 0.00 MIN. IS AN UNACCEPTABLE VALUE".
- STRAGE's cards marked TEMPORARY (`STRA 88` to `STRA 99`) drive the start depth negative when inflow exceeds the pump rate with the pump off, and the run stops (not repaired).
- SWQUAL rewinds the hydraulics file inside the restart-tape loop (`SWQU143`, `SWQU144`), so the tape holds NQCYC copies of the first quality cycle's flows.
- Transport reads `JPLOT` and never uses it.
- GRAPH reads a title card (`GRAP 30`) and then overwrites it with the tape's title (`GRAP 35`).
- HIGHRF keeps an ASSIGNed GO TO label across calls: f2c runs it, GNU Fortran stops.
- `TREA887` sets `KNTOF = 10**12` (integer overflow).
- `KILL` divides by inflow suspended solids (NaN when zero).
- Runoff's continuity check omits `WAREA(J)` on pervious storage (`HYDR137`; flows unaffected).
- WSHED reads the rain histogram once per step, at the step's middle (`WSHE 24`, `IND=1.+(TIME2-TZERO)/HISTOG`), and does not average over the step. A rain block shorter than the step is partly skipped. The 1971 decks punched rain and steps at the same interval, so they never met it; the importer makes every block a whole number of steps since 3.7. A method, not a fault.
- Storage reads tape pollutants as `((POLL(KDT,K,J),J=1,NOUTS),K=1,NPOLL)` (`STOR103`-`104`) while Transport writes `((OUTTAP(J,KK),KK=2,NPOLS),J=1,NOUTS)` (`TRAN497T`-`498`), so with two or more outfalls on the tape Storage takes coliforms as suspended solids.
- A full basin has no spill: INTERP stops the run.
- `HYDR 26` sets `NRANVL = 200` and `HYDR 51` to `HYDR 55` clear 200 elements of `HGRAPH`, `HTIME` and `RAIN`, which are dimensioned 160. Checked in the f2c build: blank COMMON is one static block of 106,244 bytes (sized by GRAPH), of which HYDRO declares 45,120. `HGRAPH(161..200)` lands on `HTIME(1..40)`, cleared by the same loop; `RAIN(161..200,J)` lands on the next column of `RAIN` and, for J = 10, on `NHYET(1..40)`; `HTIME(161..200)` lands 160 bytes past HYDRO's declaration, on `X(1..40,1)` of HCURVE's plot arrays. All of it happens before `RHYDRO` reads a card (`HYDR 63`), and every word touched is read or computed again before it is used, so nothing is corrupted in the full-program engine. The hand-translated workbench engine was not examined for this.
- Receiving Water prints a stability limit `0.75*L/SQRT(32.2*(R+2))` (card `INDA314T`); the manual's printout used `L/SQRT(32.2*(R+5))`. The manual example's 300 s step exceeds the listing's limit in 9 channels.

## What this does not show
- Not done from the outside reviews of 3.5 to 3.10: conversion still runs on the main thread (since 3.13 the engines run in a Web Worker with Cancel, and on the main thread only where a worker cannot be made; there is no automatic time limit); no mounted-tapes panel; no card-field inspector, guided experiments or network sketch; no accessibility pass (tab roles, focus handling, live region); no verification page; no autosave. The Runoff workbench's C (since 3.10 in `workbench/` and in the source archive) has been rebuilt with Emscripten 3.1.6, which reproduces the shipped engine's output bit for bit on 9 decks; the wasm itself has not been rebuilt byte for byte with wasi-sdk 24, the October compiler, and the app still runs the wasm compiled on 22 October. Nine decks are a sample: a deck that reaches code they do not could still behave differently in a rebuild. The page rebuilds from the project kit with `rebuild.sh`, which is not inside the page; the page's own download is the C and Fortran source archive, which is for reading and is not a complete rebuild (its README says what is missing). The complete package is the release zip: the page, the kit beside it, the .md, the Word file and a SHA-256 manifest. The conversion is checked against the .inp's meaning, read again from the .inp (routing, rainfall, geometry, effective parameters, inputs carried), not against EPA SWMM 5 runs: the four models in `app/test/epa/` have not been run in EPA SWMM 5.2.4 for this release, and agreement between the two embedded engines shows only that they run the punched deck alike. Inputs SWMM 1 cannot carry (the Horton cap, subarea routing, LID, groundwater, inflows, storage and the rest) are reported, not emulated. Names in quotes with spaces are not read. Zeros SWMM 1 cannot take remain approximations: a zero slope cannot be expressed on a SWMM 1 card at all, so a SWMM 5 model with level subcatchments converts to a different hydrology, and the app says so rather than fixing it. The grades come from EPA SWMM 5's source code; no SWMM 5 run was made to measure them (the session could not install the EPA solver).
- The importer is checked for what it carries (rain depth, run length, step, geometry, and since 3.9 the values SWMM 1 used) against the file, against Runoff's printout and against a second engine. Its hydrographs are not compared with SWMM 5's. SWMM 4 imports get none of the read-back or effective-parameter checks; they get the second engine when they carry quality cards. The effective-parameter audit covers subarea fields, PCTZER and channel depth, not the surface-quality cards.
- The geometry reader and the converter were written by the same hand. The review of 3.8 found two rules both had misread (the infiltration method keyword, the offset below an invert); both now follow EPA's source, cited where each rule is applied, but a third shared misreading would pass both.
- The second-engine comparison shows that two translations of the same 1,311 cards agree on the imported deck. Both read the same cards, so a card that misstates the .inp would mislead both; that is what the geometry and rainfall readers are for.
- The four status rows are screens, not proofs: Numerical validity only counts NaN and Inf tokens in the printout, Conservation only repeats what Runoff prints, and pollutant balances are not checked.
- The complexity index measures source footprint against HydroCouple = 100. It says nothing about correctness.
1. No person has compared the 10,889 cards of the Executive, Transport, Storage and Receiving Water Blocks with the page images. 17 doubtful readings are listed on the Fortran tab.
2. Storage is checked three ways: flow through a treatment plant and cost (Baker Street), and the storm-independent sizing of a basin and its plant (Wingohocking Table 5-7; Kingman Lake Table 4-3, 53 of 55 numbers identical). The routing of a storm through a storage basin is not scored anywhere: the manual's example needs an unpublished Transport tape, and Volume II's option 3 is refused by `TRCH 58`, `IF (ISTOR .EQ. 2 .AND. ITREAT(3) .NE. 35) GO TO 25`. Pollutant removals disagree with Volume II by a factor near 60 at the storm's height; the `TRAN346` explanation fits the peak hours only. Receiving Water quality has no check.
3. The Transport + Storage deck, the three-block deck and the fourteen added decks are 2026 test decks. None has a 1971 printout, so their numbers are checked against a second compiler and nothing else.
4. The five repaired cards are a 2026 judgement of what the authors meant. No person has reviewed them.
5. The Baker Street deck is in an older card format and was re-punched: one job, tapes 8/10/11; Transport control card ten fields to nine (NOUTS = 1, NNYN = 1, NNPE = 2 fixed by the three lists that follow the elements); element types 01 (inches), 02, 05 to 1 (feet), 16, 2; FILTH subarea data on one card and three HVCOLI cards of 1.0 added; GRAPH card for the listing. Type 05 as a rectangle is chosen by the printed flows (as an egg: 93 of 95 within 1 %, 6.39 vs 6.48 cfs). The 1971 values were typed from a 72 dpi scan; a few digits are ambiguous. Figure 2-5 of Volume II gives a calculated dry-weather flow of 2.70 cfs; this deck gives 2.51 cfs; not reconciled.
6. Wingohocking: typed from a rough scan (0, 3, 8, 9 often alike); sewer lengths sum to 72,565 ft vs 73,385 ft in the report; printed population subtotals differ by about 2 %. The August 3-4 storm (the one behind Tables 5-8 and 5-9) has no printed Runoff cards; rebuilt from Table 5-3 it gives 84.823 MG to the plant vs 78.091 MG printed and a second crest above the first, so the storage basin's routing is not scored. With the printed DESF = 0.50 that reconstruction stops in Storage (design flow above the largest module).
7. Cincinnati and Kingman Lake are close to Volume II, not digit matches: Table 3-1's Computed column, the SS/BOD totals of the Kingman storm (30 % and 17 % low here) and the later rows of Table 4-2 are not reproduced; figure values were read off a drawing and off printer plots (about 50 and 100 cfs). Tables 4-4 and 4-5 (plant performance, storm of 20 August 1969) and the Receiving Water profiles (Figures 4-11, 4-12) need a tape and cards that were not printed. The routing of a pumped storage basin through a storm is still unscored. Deck changes: Cincinnati tapes 8/10 and element 23 upstream 22, 24 (print: 25); Kingman GRAPH cards `9 1 3` to `9 1 0 0`, elements 36 and 82 left with blank type (manholes by `TRAN164X`), element 148 length 1.090 ft as printed, element 120 length read as 1370, BASEA 670,000 (first misread as 870,000), Receiving Water JIN = 0 and the line `QUALITY` after `ENDQUANT` dropped.
8. Volume I (Final Report) was not read. About 150 of Volume III's 359 pages were read.
9. REAL is IEEE single precision, not IBM System/360 hexadecimal. Expect three to four digits of agreement with 1971 printouts. System/360 single precision is base 16 with a 24-bit fraction, of which 21 to 24 bits are significant, and its arithmetic truncated where IEEE rounds, so long sums drift apart in the last digits; the 4 dollar differences in six Baker Street cost totals near 1.7 million dollars are of that size, though they were not traced to it.

## How to reproduce
- In the app: Run tab, press the "Receiving Water" example button (or pick "Receiving Water: User's Manual estuary" and Load sample). The check card recomputes the 52-value comparison. Samples "Transport" and "Transport → Storage" mount the constant-inflow tape (50, 40, 30 cfs at elements 101, 109, 107) on unit 8.
- Baker Street: Run tab, button "1971 city: Baker Street" (or the sample list group "A 1971 deck for a real storm"). The check card recounts the 95 numbers. `python3 tools/mk_baker.py DIR [egg]` writes the deck; `python3 tools/score_baker.py OUT.txt` scores a printout.
- Wingohocking, Philadelphia: Run tab, button "1971 city: Wingohocking" (or the sample list). The check card recounts Table 5-1. `python3 tools/mk_wingo.py DIR` writes the 3 July 1967 deck from `tools/wingo_data.py`; `python3 tools/score_wingo.py OUT.txt` scores a printout; `python3 tools/mk_wingo.py DIR aug --qdes` writes the August storm with the storage basin sized as in Table 5-7.
- Cincinnati and Kingman Lake: Run tab, buttons "1971 city: Cincinnati" and "1971 city: Washington", or the sample list. `python3 tools/mk_cinci.py DIR`, `python3 tools/mk_king.py DIR` write the decks; `python3 tools/score_v2b.py cinci|king|design OUT.txt` scores a printout. The Kingman storage sample needs "run with the 2026 repaired cards".
- Added decks: Run tab, sample list group "Parts of the program the first examples never reached", or the "Printer plots" button; then the Plots tab. Tick "run with the 2026 repaired cards" for the three decks that say they need it.
- The scripts named here are in `swmm1-c-source.zip` (Fortran tab, "Download the C") under `tools/`, with the 1971 reference values under `reference/`. Since 3.7 they find their folder from their own location (or `SWMM1_ROOT`); no machine path is written in. There is no public repository yet.
- Release package (since 3.11): `swmm1-engine-v3.11-release.zip`, one folder holding the page, `kit/swmm1-engine-project-kit.zip`, this .md, the Word file, `README-RELEASE.md` and `MANIFEST.sha256`. Check it with `sha256sum -c MANIFEST.sha256`; serve the folder as it is (Netlify: drag it in) and the Fortran tab's "Download the project kit" button finds the kit beside the page. The claude.ai artifact cannot host a zip, so there the button says where the kit is.
- The project kit carries `KIT-MANIFEST.sha256`; `./rebuild.sh verify` checks every file of a fresh unzip against it (before building, since a build rewrites three files). `./rebuild.sh release` makes the kit and the release package (`tools/mkrelease.sh`).
- Whole page from the project kit: `./rebuild.sh` (page, Word file, source archive, then `t16.js` to `t19.js` and `t21.js` to `t23.js`; exit status 1 if any step, comparison or test fails, with the failures named); `./rebuild.sh engines` first rebuilds both full-program engines from the listing and compares them with the shipped ones; `./rebuild.sh all-tests` runs every browser test. Output goes to `$SWMM1_OUT`.
- Runoff workbench from its C: `workbench/build.sh` (in the kit and in the source archive) builds it natively, natively with `trig_parity.h`, and with Emscripten 3.1.6, and compares all three with the shipped `runoff_v14.wasm` on every deck in `workbench/decks`; `./build.sh mathlog` adds the call-by-call math-library logs; `WASI_SDK=/path/to/wasi-sdk-24.0 ./build.sh` adds the October compiler and a byte-for-byte comparison. `workbench/README.md` gives the commands by hand.
- From source: download the whole listing on the Fortran tab; apply the build-time edits above; `gfortran -std=legacy -fno-automatic -ffixed-line-length-72 -fallow-argument-mismatch -fno-range-check -finit-local-zero`, or `f2c -E` then any C compiler with libf2c.
