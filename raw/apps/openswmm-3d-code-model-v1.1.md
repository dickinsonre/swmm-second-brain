# OpenSWMM 3D Code Model: the OpenSWMM engine source drawn as a city, one building per file

## In three points
- **What:** Draws the OpenSWMM engine source (swmm6_rel at b92a4f1, 2026-11-11) as a city: 925 hand-written source files as boxes, with include links, git activity and change since the previous survey.
- **So what:** Of 482,467 lines, the legacy SWMM 5 tree holds 64,205 and the new engine 366,435; SWMMEngine.cpp is the largest file at 12,364 lines and the busiest, with 222 commits in 90 days.
- **Now what:** Use it to see where SWMM6 work is happening before reading code. Tests (595 files) are excluded, it is one commit of an alpha that moves daily, and no person has checked the numbers against the repository.

## What it does

It answers "what is in the OpenSWMM engine source, how big is each part, what depends on what, and where is the work happening" for engineers who will not read 482,467 lines. Every hand-written source file under `src`, `include` and `python/openswmm` becomes one box. Folders are platforms. Clicking a box draws its `#include` links. Height and colour can be switched among size, dependence, git activity, change since the previous survey, lineage and branching. Outputs: the interactive page, a CSV of every per-file number, a PNG of the view, a WebM recording of the tour, and a `.glb` 3D file of the same geometry.

## How it computes

Survey (Python script `analyze.py`, run once per build, not shipped in the page):

1. Clone `swmm6_rel` with full commit history (`--filter=blob:none`). Walk `src`, `include`, `python/openswmm`. Keep files with extensions c, cpp, h, hpp, pyx, pxd, py, pyi. Skip any file whose first 200 bytes contain "Generated by Cython".
2. Lines: `L` = newline count, plus 1 if the file does not end in a newline.
3. Code and comment lines: a comment stripper for `//`, `/* */`, `#` and Python docstrings. String literals are not parsed. Approximate.
4. Include links: each `#include "x"` or `<x>` is resolved, in order, to (a) the path relative to the including file, (b) one of the project include directories, (c) a unique base name in the tree. Cython `cdef extern from "x"` is resolved the same way. Unresolved quoted includes: 12 (build-generated headers and data files). Unresolved angle includes: 2,303 (system and library headers).
5. Depended on by (`included_by`): number of files that include this file directly.
6. Rebuild reach: number of files that include this file directly or through other files (transitive closure of step 4, inside the model only).
7. Git history, by path, renames not followed: `git log --name-only` over the three roots gives commits per file (all history, and the 90 days before the head commit), days since the last commit, days since the first.
8. Change since the previous survey: `git diff --numstat d8c0a1e b92a4f1` gives lines added and deleted per file; `--name-status` gives new and removed files.
9. Branch points: count of `if for while case catch && || ?` in C and C++ after comment removal (`if elif for while except and or` in Python). Shown per 100 code lines. Approximate, not cyclomatic complexity.
10. Districts: `src/engine/<dir>` is district `<dir>`; `src/legacy` and `include/openswmm/legacy` are `legacy`; the rest of `include` is `api`; `python/openswmm` is `python`; other `src/<dir>` are named by `<dir>`.

Layout:

- Squarified treemap, nested by folder, in a 1000 x 1000 square. Weight of a file = `sqrt(max(L, 25))`.
- Lot area `w * d` is therefore proportional to `sqrt(L)`.
- Height in "Lines" mode: `h = k * L / (w * d)`, with `k` set so the tallest box is 260 units. Volume `w * d * h = k * L`.
- Other height modes are linear: `h = 2 + 258 * value / max(value)`.
- A platform is 1.6 units thick; a file sits at `1.6 * (number of folders in its path)`.

## Inputs and outputs

- Input: none at run time. All data is embedded in the page as JSON.
- CSV export columns: path, district, ext, lines, code_lines_approx, comment_lines_approx, included_by, includes, rebuild_reach, commits_all, commits_90d, days_since_last_commit, branch_points_approx, added_since_prev, deleted_since_prev, spdx, epa_swmm5_header, lot_w, lot_d, height_lines_mode.
- PNG export: the current 3D view. WebM export: the nine-stop tour with captions. Markdown export: this file.
- `openswmm-3d-code-model.glb`: binary glTF 2.0, one mesh, vertex colours by district, 994 boxes (925 files and 69 platforms), 1000 layout units scaled to 10 model units.

## What this does not show

1. Tests are excluded: 595 files, 271,673 lines (56 percent of the model's size).
2. One Cython-generated C file is excluded: 33,790 lines.
3. Documentation (536 files) and example models (381 `.inp` files) are excluded.
4. An include link is a compile-time fact. Calls through the C API, run-time plugins and Python scripts are not links.
5. Rebuild reach ignores the build system and counts only files in the model.
6. History is by path. A renamed or moved file shows only its history since the move. No path here is older than 300 days although the log goes back to 2014-03-14.
7. Code/comment split and branch points do not parse string literals.
8. Lines are not difficulty and commits are not quality.
9. The baseline for "changed" is one day. It is a demonstration of the comparison, not a trend.
10. One commit of an alpha that moves daily. Rebuild before quoting a number.
11. No person has checked the numbers against the repository. The exports and recording were tested only in headless Chrome, not inside the claude.ai artifact frame or on Netlify.

## How to reproduce

1. `git clone --filter=blob:none --single-branch -b swmm6_rel https://github.com/HydroCouple/openswmm.engine && git checkout b92a4f19b2ad4fc441261ac499d184fa789d20d1`
2. File count: `find src include python/openswmm -type f \( -name '*.c' -o -name '*.cpp' -o -name '*.h' -o -name '*.hpp' -o -name '*.pyx' -o -name '*.pxd' -o -name '*.py' -o -name '*.pyi' \) ! -path 'python/openswmm/legacy/engine/_solver.c' | wc -l`
3. Line count: the same `find`, piped through `xargs cat | wc -l`.
4. Change: `git diff --numstat d8c0a1e b92a4f1 -- src include python/openswmm`
5. Per-file numbers: Export, "Census as CSV" in the page.

The survey script `analyze.py` and the build scripts are not yet published. Section "How it computes" is the full specification.
