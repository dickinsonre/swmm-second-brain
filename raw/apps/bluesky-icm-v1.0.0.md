# BlueSky-ICM: five blue-sky tools for SWMM5 and ICM on EPA SWMM 5.2.4 in the browser

## In three points
- **What:** One HTML file holding the five tools of Bob's Lovable bluesky-scaffolder (ModelDiff, RainLab, CalibrationCopilot, FloodLens, ScenarioStudio) with EPA SWMM 5.2.4 compiled to WebAssembly underneath all five. The scaffolder's Lite engine stays beside the real one as a foil, with its units corrected.
- **So what:** The scaffolder's report readers were wrong as shipped: its continuity regex captured the dot leaders, so every report read 0.00% (the demo reads -0.033 and -0.041%), and its node flooding parser counted days and hh:mm as one token, so flood volume read 0. The wasm engine's .out is byte-identical (168,018 bytes) and its .rpt line-identical to a native gcc build on both demo models.
- **Now what:** Use it to try the five ideas on a real engine with two scripted demo models. Ponded depth is a 1D stand-in for surface depth, the damage and cost numbers are assumptions, and nothing reads InfoWorks ICM networks despite the name.

This summary was written after the fact. The page ships no technical summary of its own. Its version and date are the page's own ("Version 1.0.0 · built 2026-10-21"). The file name above is ours. Every number below is copied from the page. Nothing was run to write this file.

## What it does

Tabs: Hub, ModelDiff, RainLab, Calibration, FloodLens, Scenarios, About, Doc. ModelDiff compares two versions of a model; RainLab builds design storms (Chicago, Huff, NRCS Type II); CalibrationCopilot fits against synthetic gauges with a local search; FloodLens rates node hazard; ScenarioStudio runs alternatives. The engine runs in a Web Worker with a main-thread fallback. Demo models Lower Basin v23 and v24 were generated by script: CFS, curve-number infiltration, dynamic wave with ponding, 11 junctions, 11 conduits, 11 subcatchments and a 2-hour Chicago storm (2.75 in in v23, 3.3 in for v24's 100-year case); v24's changes are chosen to exercise ModelDiff.

## Checks (as stated on the page)

- Library suite in Node on real engine output: 34 passed, 0 failed (engine identity, report and .out readers against printed values, all 12 node depth maxima equal to the report's Reported Max Depth, the diff, the storm tables, the Lite engine).
- Engine identity: return code, version 52004, .rpt line-identical and .out byte-identical to a native gcc build on both demo models.
- Headless Chromium 1194, 2026-10-21: all eight tabs and every tool run in both themes, 0 console errors, no text below WCAG contrast targets, no horizontal scroll at 375 px; theme changes no computed number; worker and main-thread paths give the same 82.06 cfs outfall peak.
- The Huff table checked against ISWS Circular 173 and the hazard thresholds against the Defra/EA 2008 note. The NRCS Type II table was not checked row by row.

## What this does not show

As the page lists it: ponded depth at a node is a 1D stand-in for surface depth; velocity, the damage curve and every capex number are assumptions; synthetic gauges come from the model itself; the copilot is a local search; nothing reads InfoWorks ICM networks.
